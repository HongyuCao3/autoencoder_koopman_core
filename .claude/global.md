## 报告口径（硬约束）

> **判分的选择/报告分离**：自判分数（模型给自己打分）是**选择信号**，独立重判是**报告信号**。
> 二者永不混用。依据：2026-09-03 的独立 judge 重跑发现 **self-judging bias 是单向漏检，
> 藏了 4× 的 effect size**——那批数在被发现之前已经作为结果流通过。

**唯一可以作为结果报告的数字**（论文、幻灯片、weekly、任何跨臂/跨配置比较）：

- 来自**独立重判**（`rejudge`），不是产出轨迹的那个模型的自判；
- 跨 **≥3 个不同 seed** 聚合；
- 写成 **`mean ± std (n)`**，`n` 是 seed 数不是样本数（样本数另写）。

**明令禁止作为报告/比较的头条数字**：

| 禁止 | 为什么 | 历史 |
|---|---|---|
| 自判分数 | 单向漏检，systematically 低估效应 | 藏了 4× effect size |
| 单 seed 点估计 | 没有误差棒，不可比 | — |
| 2 seed | 分不开臂 | 「Phase J：预算设定成立，但 2 seeds 分不开臂」 |
| 训练/拟合损失、一步预测误差 | 是拟合诊断量，不是任务结果 | — |
| 用来选模型/选阈值的那个量 | 选择信号不能同时当报告信号 | — |
| "平均排名"等序数聚合 | 跨表不可比 | — |

**选择在自判上做、报告在重判上出**，两者解耦。选完之后必须重跑一次重判才有可报告的数。

**这条规则必须有可执行守卫。** 参照本仓库既有的 `persona_drift.run_config_guard`
（它防的是"一份报告平均了两个控制器产出的轨迹"，元测试见
`tests/test_run_config_guard.py`，其 docstring 说明了原理：**守卫若静默通过，
它要防的失败模式在报告里就是不可见的**）。守卫与其元测试**不得删除**，
不得为了让某次运行通过而绕过——去改配置，不要改守卫。

## null 结果的默认后果是**关闭**

- **"上次可能是仪器问题"不构成续做理由。** 这个理由永远成立，所以它什么也不筛。
- 续做需要一个**独立的、正面的**理由：新数据源、新效应量级、或论文里一个必须填的空格。
- **同一个仪器只修一次。** 第二次同一仪器出问题 = 效应量级配不上这个仪器的精度，
  **换任务或换效应，不要换 judge。**（历史：judge/readout 这条链修了四轮。）

## 产物与谱系

- `persona_drift_control/outputs/`（99 个 run 目录）**只增不改**，不覆盖任何已有产物。
- 每个 run 目录必须能回答：**它是在哪个 harness 版本下产生的。** 缺这个字段，
  harness 一改就只能全量重跑——这是 ERGO 那 18 个作业的直接成因（`docs/LEDGER.md` §2）。
  最低要求：run 配置里记 `git rev-parse HEAD` 与关键开关（`reset_mode` / `prompt_profile` /
  judge 版本）。
- 产物命名要让人一眼看出这个数是什么意思，不要用无信息的通名。
