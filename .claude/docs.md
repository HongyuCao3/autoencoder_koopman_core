# 文档规则（`docs/**`）

先读 `.claude/global.md`。术语基准 `docs/NAMING.md`——**新增文档前先读它**。

纯 Markdown，**不引入 Quarto 等构建工具**（项目既定决策，见 `docs/README.md`）。

## 文档权威序（冲突时按此裁定）

1. `docs/NAMING.md` — 术语。任何文档与它冲突，改文档。
2. `docs/task/*.md` — 任务定义与选型
3. `docs/article/PAPER_EXECUTION_PLAN.md` — 论文主张与叙事弧
4. `docs/method/*.md` — 方法实现细节
5. `docs/experiments/*.md` — 实验记录（含结论）
6. `docs/feasibility/*.md` — 候选方向可行性
7. `docs/README.md` — 索引与导航。**不作为内容权威**，只作为入口。

**若两处冲突，不要自行选一边——标出冲突并问用户哪个权威。**
（历史：`method/overview.md` 曾与 `koopman_surrogate.md` 互相矛盾，靠一次人工 sweep 才发现。）

## 写作纪律

- **计划文档 ≤ 150 行。** 超出的部分是结果，写到结果文档。
  *计划比它委托的代码长 = 该停下来的信号。*（历史均 425 行，最长 1336 行。）
- 计划文档的 outline **由用户写**（≤10 行，含闸门准入三行）；agent 只负责把 outline 填成
  可执行规格。agent 独立起草计划时的默认倾向是"再加一个稳妥的前置检查"——那在局部永远正确，
  在全局就是漂移。
- **不要把 `.claude/` 的规则重抄进计划文档。** 重抄就是漂移的入口——每个会话从计划文档
  重新学规矩，规矩就会各版本不一。引用路径即可。
- 一次只有**一份活跃计划**。开新的必须先给旧的写状态横幅（✅完成 / ⛔终止 / ⏸挂起）。
- 历史陈述**不改**。文档里的旧命名如果是对当时事实的正确记述，改掉就是篡改记录；
  只改"顶层身份表述"（这个项目现在在做什么）。

## 结果表

更新结果时**不要动文档的结构、图和结论段**，只填数。
