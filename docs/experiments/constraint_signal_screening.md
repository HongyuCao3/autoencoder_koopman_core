## 一、机制类别与正确的探针形式

本线的机制不是 routing/specialization，是**闭环控制**。但它落在 H1 同一个结构族里：
闭环的价值全部来自**反馈状态 Z 携带了开环日程不知道的、关于动作收益的信息**。
所以探针不是无条件互信息，而是**条件**量：

> **I( y_t ; Δy_{t+1} | t ) > 0**，其中 `Δy_{t+1} = y(u=1) − y(u=0)` 是同前缀反事实增益。
>
> `| t` 这个条件是全部要害。轮次是**确定性外生量**，开环日程免费拥有它。

| 符号 | 本线的取值 |
|---|---|
| Z（状态） | `y_{t}` = 当前满足的活跃约束数 / k，k=3；副读出是 3 维逐约束判决向量（**8 种满足模式**） |
| X（条件） | 轮次 t（以及题目 id） |
| Y（目标） | 提醒再注入在下一轮带来的增益 `Δy_{t+1}` |

**两条已死的线，死因正是这个量，而两次都没有作为开线前筛查跑过：**

| 线 | 死在哪一步 | 实测 |
|---|---|---|
| `defense` | 更早一步：**读出根本没有量程** | 独立 judge ceiling share 0.91；turn 1 `mean=1.000 sd=0.000 distinct=1` |
| `ERGO` | **I(状态;增益 \| 轮次) ≈ 0** | `Δc ~ entropy` 的斜率在控住 `shard_frac` 后从 −0.2453 衰减到 −0.0070（**97%**）；唯一存活的预测量是轮次本身；后果是模型最优日程对 **135/135** 条轨迹完全相同 |

> **这条线要买的东西**：k=3 让状态在**每个轮次内部**有 8 种取值，而轮次本身编码不了它们。
> 如果 `Δy` 只跟"第几轮"走、跟"这一轮丢的是哪一条"无关，本线与 ERGO 是同一个失败，
> **必须在建 Koopman 拟合和 MPC 之前发现**。

## 二、S0-0 筛查臂：把 EK-A 的设计放到最前面，而不是最后

ERGO 的账单是 18 个作业回答同一个问题，而最终唯一奏效的**反事实分叉**设计是在最后才想出来的。
本线**反过来**：分叉臂是第一个 GPU 动作，规模是 S1 的零头。

**设计**：N=12 个对话 × T=20 轮，base 走 `zero_control`；**每一轮从逐字节相同的前缀分叉一次**，
在该轮改施 `u=1`（重述全部 3 条约束），只重新生成该轮 → **240 个同前缀反事实对**（实际为 **228**，第 1 轮不可施 u=1；见 §十 第 1 条）。
（对照：S1 是 160 轨迹 × 20 = 3200 行。）判分复用 S0 定下的两个 judge。

**为什么是分叉而不是观测式激励**：同前缀配对把前缀方差整体消掉，噪声下界比观测式低一个量级
（ERGO 实测每 GPU-秒信息量约 7 倍）。前提 (iii) 是本线唯一真正的未知，不该用钝仪器去问。

## 三、三道闸门，阈值与 MDE 一并预注册（跑前定，跑后不改）

**每道闸门的判定必须与本设计的 MDE 同址报告。** 不附 MDE 的"CI 跨 0"什么也没证否
（ERGO 失败模式 29；`koopman-judge-dynamics-not-prediction` 陷阱 3：MDE 必须与被检验的量同单位）。

| 闸门 | 判据 | 过了 → | 不过 → |
|---|---|---|---|
| **K1 读出量程** | 每一个 t ≤ 20 上：跨轨迹 `sd(y_t) > 0` **且** ≥3 个不同取值；且 8 种满足模式里至少 4 种在整个臂中出现 | 进 K2 | **关线**。这是 `defense` 的死法，**不许第二次修 judge/readout** |
| **K2 状态超出轮次**（本线的存亡问题） | `Δy_{t+1} ~ y_t + t` 中 `y_t` 系数的 item 自举 95% CI 不含 0，**且**相对不含 `t` 的边际估计**衰减 < 50%** | 进 K3，S1→S3 照计划走 | **关线或降级为开环主张**。这是 `ERGO` 的死法（衰减 97%） |
| **K3 执行器权威** | `mean(Δy) > 0` 且 CI 不含 0，**且实测效应 ≥ 本设计的 MDE** | 进 S1 | 报告，交裁决 |

**K2 的衰减阈值为什么是 50%**：ERGO 实测 97%（纯代理），一个真状态应当远低于它；
50% 是"一半以上的解释力来自轮次以外"的操作化，取整数便于跑前锁死。**这是 go/no-go 过滤器，不是可发表的测量。**

## 六、先验与锚例（`intuition_lattice` 候选，趁现在写下）

**先验（一句话）**：约束保持的失效是**逐条独立掉落**的，不是整体退化——
所以"现在丢的是哪一条"携带了"该提醒什么"的信息，而这信息**不是轮次的函数**。
这正是 `defense`（二值安全分）与 `ERGO`（标量 closeness）都没有的结构。

**借来的权威**：SEQUOR（Canaverde et al., COLM 2026）逐约束判决 `ConstraintEvaluation.followed`
是上游已有仪器，我们**只换聚合方式**（上游 `all()` 成二值，我们保留计数），不造新仪器。

**锚例候选**：`resources/sequor/sequor_tuples3.jsonl` 的 200 个对话中，约束在**第 1 轮说一次、
之后 0 次重提**（200/200 核过），因此"第 t 轮还满足几条"是纯粹的保持量，没有任何重提在暗中托底。

**待检验假设（P8）**：*移除状态反馈（改用同代价固定日程）会在约束掉落模式异质的对话上变差，
在同质对话上影响很小。* 由 S3 的三臂对比检验。

## 七、论文里的三句话与那张表的空壳（*开一条新任务线* 第 3 步）

> 多轮对话中，一次性给出的约束会随轮次逐条掉落，而掉落的是**哪一条**在不同对话之间不同。
> 我们把"重述约束"当作一个有预算的执行器，用 Koopman 算子从同前缀反事实数据里辨识它的一步增益，
> 再问一个开环日程回答不了的问题：**等代价下，按状态决定何时提醒（以及提醒哪一条），能否赢过最优固定日程。**

**不填这个空壳的实验不跑：**

| 臂（等预算 k） | `y_late` mean ± std (n=seed) | vs 固定日程的配对差 95% CI | 代价 `inserted_tokens` |
|---|---|---|---|
| `koopman_mpc` | | — | |
| 等代价随机分配 | | | |
| 同代价最优固定日程 | | | |

数字口径按 `.claude/global.md` → *报告口径*：≥3 seed、`mean ± std (n)`、报告 judge 独立于 in-loop judge。

## 九、S0 的两个零 GPU 前置发现（2026-09-08，在挑 judge 之前算的）

### 9.1 gold 集有长度混淆：`violate` 系统性更长

| label | 回复词数 median | mean | p10 | p90 |
|---|---|---|---|---|
| `follow` | 378 | 383 | 69 | 660 |
| `violate` | **478** | 471 | 242 | 699 |

500 个 `(task, constraint)` 格子在两个 label 上**完全配对**，配对内 `follow` 更长的只有
**174/500（34.8%）**，中位差 **−72 词**。因此一个只看长度的"judge"就能拿到：

| 只看长度的规则 | 准确率 |
|---|---|
| 配对内"短的那条是 follow" | **64.8%** |
| 不配对"短于中位数就是 follow" | **59.7%** |

**追加闸门 G-S0-0（长度地板）**：任何候选 judge 必须**同时**报告它在同一批 gold 上的准确率
**与上面这两个长度地板**，且相对配对地板 64.8% 的提升要写进报告。
**只报"准确率 0.8x"而不报地板 = 不知道这个 judge 有没有在读约束。**
依据与 ERGO 的死法同源：`null` 必须拿到每一个廉价的外生信号
（那里是轮次，这里是长度；见 `koopman-judge-dynamics-not-prediction` 第 (d) 条）。

> 这**不**推翻计划 §3 的 G-S0-1（一致率 ≥0.80 且 κ ≥0.60）——0.80 本来就够不到用长度刷出来。
> 它管的是**中间区间**：一个 0.72 的 judge 距离长度启发式只有 7 个点，不该被当成"够用但弱"。

### 9.2 gold 的约束池与我们要跑的对话只部分重叠

| | 数量 |
|---|---|
| gold 集里的不同约束 | 500 |
| 我们 200 个对话用到的不同约束 | 439 |
| 两者交集 | **163**（占 gold 的 32.6%，占我们的 37.1%） |

按对话看覆盖：

| 3 条约束里有几条在 gold 里 | 对话数 |
|---|---|
| 3/3 | **16** |
| 2/3 | 46 |
| 1/3 | 83 |
| 0/3 | 55 |

**后果，分两层，不要混为一谈：**

1. **S0-0 筛查臂（N=12）用那 16 个全覆盖对话。** 判分器恰好在它要打分的那些约束上被校准过，
   K1/K2/K3 因此不背"judge 在没见过的约束上失灵"这个额外的不确定性——
   筛查臂的任务是判定**状态是否存在**，不该同时承担仪器外推的风险。
2. **S1/S3（N=40）做不到全覆盖**（只有 16 个）。那时必须逐字写明：
   **报告 judge 有约 63% 的约束是在校准集之外的**，并按 9.1 的地板一并报告。
   若要买回这一格，唯一干净的做法是在 S0 里对**未覆盖约束**另抽一个小人工核验集，
   **不是**把 N 缩到 16（那会把题集偏向"容易判"的约束，且 N=16 撑不起 S3 的功效）。

## 十、规格增补（2026-09-09 起用户签字；起草四条，其后逐条追加至九条）

工程实现时暴露的四处规格空白。**每条都在跑第一个 S0-0 作业之前定死**，判据写在这里，
代码在 `scripts/analyze_sequor_s0_0_gates.py` / `scripts/run_sequor_s0_0_branch_arm.py` 里，
有单测（含植入的正/负对照）。

1. **对数是 228，不是 240。** 第 1 轮本身就带约束块（约束在第 1 轮说一次），
   所以 u=1 在第 1 轮不是一个动作——剂量差恒为 0，只会稀释效应估计。
   T=20 → 每题 19 对 → N=12 时 **228 对**。**闸门阈值不变**，MDE 按实际存在的对数算。
   `sequor_bank.user_message` 对 turn 1 的 `remind=True` 直接拒绝。

2. **K2 有第三个判定 `UNDECIDABLE`。** 以下任一成立即判不可判定并交还用户，
   **不算 FAIL**：① `y_prev` 的 IQR = 0 或不同取值 < 3（x 轴压平，回归没有自变量——
   EK-A 的 `c_prev` 就是 IQR 0、75% 的行挤在一个值上）；② 斜率的 MDE 大于整体平均增益
   `mean(Δy)` 的绝对值（这个设计连"状态效应大到等于全部平均效应"都分辨不出来）。
   **理由**：FAIL 的后果是关线，而没有功效的闸门不该关线——ERGO 的闭合前审查就是在这一点上
   否掉了"关线"的结论。

3. **三道闸门在独立（报告）judge 的读出上算。** 自判读出只用于按 `u` 拆分比对两个 judge
   的系统性差距（计划 §2 那条"judge 错误率可能与 `u` 相关"的第一手、较弱的答案，
   **不替代**那条强 judge 抽样对照）。理由：K1 问的是"可报告的读出有没有量程"，
   这正是 `defense` 线的死法，用选择信号去判它会重演。

4. **agent 回复 cap = 1024 token，且触顶率 > 5% 视为不合格。** 上游未报生成超参；
   gold 回复中位 429 词 / p90 679 词，cap 咬住就等于在测截断而不是测约束保持。
   `run_sequor_s0_0_branch_arm.py` 逐行记 `finish_reason` / `hit_token_cap` 并在超过 5% 时告警。
   **修正（2026-09-09 第二次裁决，选项 a）**：cap **1024 也不够**。15756689 触顶 18.6%，
   且 **75/87 集中在 2 题**——它们的约束本身要求写长（`tuple_294_1`「Write a longer dialog」100%、
   `tuple_245_1`「Write creatively as a story」92.3%），另一头 `tuple_399_1`（「under 100 words」）
   中位 96 token、`tuple_247_1`（「line length ≤ 100 characters」）中位 47。
   **所以长度是约束集合的函数，任何全局 cap 都不中性**：它在"要求写长"的约束上制造违规。
   现行规格：**cap = 2048、`max_model_len` = 49152**（20 × (2048+120) ≈ 43k，32768 会静默丢掉
   最早那几轮——而约束就是在第 1 轮说的），**触顶判据按题算、阈值 5%**。
   **仍有单题超标 → 报告并交还**，不再自行抬 cap、不自行剔题：
   `run_sequor_s0_0_branch_arm.py` 写 `token_cap_by_item` / `items_over_cap_criterion`，
   `analyze_sequor_s0_0_gates.py` 的 `refuse_if_the_cap_bound()` **拒绝**这样的臂，
   唯一的通过方式是逐个 `--exclude-item`（并写进闸门报告，与它改动的那些数同址）。
   **按"约束要求写长"剔题会把题集偏向容易保持的约束——那是关于设计的发现，不是可以顺手抹掉的细节。**

   **另一处同源修正**：判分 cap 512 是在 14B 上测的（smoke 15719117），
   对 4B 不成立（解析失败 8.1%，其中 149/162 是触顶；判词 p90 463 token vs 14B 的 194）。
   自判那一遍的判分 cap 取 **1024**，失败率就在 S0-0 的判分产物里量——不为它另开仪器作业。


5. **保真度 harness，与随之而来的两处判据改动（2026-09-09 第三次裁决，「按照你的建议执行」）。**
   保真度臂（job 15761176）证明 S0-0 的读出天花板是**我们的 harness** 造的：
   {约束放 system message} × {模型自带默认采样} **两个旋钮同时**换掉，上游可比读出才落到
   **t1 = 0.42 / t20 = 0.08**（上游 ≈0.50 / turn 50 才 <0.12），按题配对差
   **−0.3292，CI [−0.5375, −0.1333]**；**任一单独换都过不了判据**（−0.033 与 −0.075，CI 都含 0）
   ——是交互，不是两个可加效应。分级读出上天花板份额 **0.529 → 0.200**、地板份额仅 0.017，
   K1 的不合格轮次由 3 轮降到 1 轮（只剩 t1）。现行规格：S0-0 臂在该 harness 下重跑，并且：

   - **K1 的范围改为 t2..t20。** 第 1 轮说出约束、不接受 u=1、**产出 0 个反事实对**
     （与本节第 1 条的"228 对而非 240"是同一个事实）。用一个不产出对的轮次去决定
     "喂给 K2/K3 的读出有没有量程"，是让闸门去判它管不着的东西。
     **t1 的统计仍然计算并写进产物**（`per_turn_out_of_scope`），所以这个范围**不能**用来
     藏一个饱和的读出——单测两条：范围外的饱和 t1 不再挂 K1、范围内的饱和轮次照挂。
   - **seed 数从 1（greedy 单遍）改为 3。** 采样把噪声放进了每个反事实增益里：前缀仍逐字节相同、
     Δy 仍无偏，但方差变大 → K2/K3 被比对的 MDE 抬高。反事实对**按 seed 配对**，跨 seed 不成对

7. **K2 的功效条款移到 FAIL 分支（2026-09-09 第五次裁决，「按照b执行」）。**
