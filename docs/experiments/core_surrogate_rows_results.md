## 三条读法

**1. 记忆有用，但不是普遍有用。** 3/7 显著支持（+0.603 / +0.312 / +0.235，都是 n≥42 的任务）、
**1/7 显著反对**（`average_word_length_t5` −0.409，n=14）、3/7 分不开。
**不能写成「惯性假设成立」**，只能写成「在读出有量程、样本足的任务上成立」。
这与 `ABLATION_STUDY.md` 第五阶段「任务相关、无统一方向」一致，不是新矛盾。

**2. 非线性买不到东西——但这句话要用效应量讲，不能用显著性讲。**
`ours − AE` 与 `ours − LSTM` 在所有有信息的任务上都在 **±0.03 以内**，且符号在任务间翻转。
其中两格名义显著：`vector_count_stage2` 的 vs AE **+0.005 ★**、`character_length_t5` 的
vs LSTM **−0.031 ★（LSTM 更好）**。配对 bootstrap 精确到能把 0.005 判显著——**显著且可忽略**。
所以措辞是「差别 <0.03 且方向不一致」，**不是「统计上不可区分」**（后者是错的）。

**3. 「执行器进了算子」这条主张，core 一格都撑不住。**
`ours − 无 r` **七个任务全部跨 0**。原因是设定不是方法：core 的 `r` 每条轨迹**恒定**、不是
随机化的动作，延迟嵌入状态已经把它编码进去。这条主张只能由三条行为线扛
（`defense` 的 `B`=+0.0825、`constraint` 的 +0.0182，CI 均不含 0，因为那里 `u` 是伯努利随机化的）。
**Table 1 第 3 行的读法须据此改写**（待办，记在 `MAIN_TABLE_DESIGN.md`）。

## 执行中抓到的两个 bug（都在出数之前）

1. **按位置对齐是错的。** `rollout_augmented_from_trajectories` 内部用 `sort_values("turn")`，
   pandas 默认 **quicksort 不稳定**，吐出的轨迹顺序是任意的。第一次 smoke 里 LSTM 被打
   **−26.9**（比 null 差 27 倍），根因是每条预测和**另一条轨迹**的真值配了对。改为按
   `(trajectory_id, turn)` 显式对齐后变成 **+0.423**。回归单测：把轨迹顺序倒过来，六行分数逐位不变。
2. **误差棒口径不一致。** 第一版给确定性行按轨迹 bootstrap CI、给 AE/LSTM 跨 seed 的 sd，
   两个不同的量印在同一列，AE 看起来比旁边的线性拟合精确 100 倍。现在所有行的点估计与 CI
   都来自**跨 seed 平均后的逐行平方误差**，跨 seed 离散度单独报（`seed_spread_*`）。

## 同址必带的局限

1. **三个任务没有信息量**：`even_odd_t5`(4 条轨迹)、`sentiment_t5`(10)、`average_word_length_t5`(14)。
   后两个上 ours 的 CI 是 [−0.11,+0.78] 与 [−1.52,+0.40]，跨 0 跨得毫无意义——
   这三列只能报「本设计分辨不出来」，不能当结论报。
2. **误差棒不含数据采样的 seed 维度**：core 的 3 个 seed 是**训练** seed，数据只有一份。
   行为线的 3 个 seed 是数据 seed。两者的 `n=3` 不是同一件事。
3. **`ddof` 口径未签**（`MAIN_TABLE_DESIGN.md` §六第 5 条），产物同时存 ddof=0 与 ddof=1 两套。
4. LSTM 的隐层大小在 **validation** 上选（8/16/32），report 用 test；**未按任务调过其它超参**。
