## 零、证据基础（2026-09-07 复算，零 GPU，可复现）

### 0.1 信息结构：可预测的部分事先就知道，事后观测没有预测力

闭环控制的价值是**用观测换预测**。在 **255 条轨迹**（全部有 rejudge 子目录的开环臂，
已剔除前两轮就插过提醒的轨迹）、30 个攻击上实测：

| | 事后观测：前两轮均分 → late(3–5) | 事先可知：攻击身份（**留一法**样本外 R²） |
|---|---|---|
| 自评 judge | r = **−0.066**（p=0.291） | **0.571** |
| 独立 judge | r = **+0.041**（p=0.515） | **0.453** |

"留一法"= 用**同一攻击的其余轨迹**的 late 均值预测这一条，不是自我拟合。

**两个必须写清的限定**：
- 独立 judge 下前两轮 **98% 是满分**（turn1 sd=0.016、turn2 sd=0.035），所以那里的 r≈0
  有一半是"没有信息可关联"，不能单独当证据；
- 自评下前两轮确实有变化（turn2 有 18.8% 非满分，turn1–2 均分 sd=0.070，late sd=0.241），
  n=255 能排除 |ρ|>0.12，所以"早期观测解释 late 方差不到 2%"是站得住的。

### 0.2 方差分解：有东西在动，但在有效口径下是噪声

行级方差分解（同一批 1905 行）：

| | 攻击之间 | 同攻击内不同轨迹 | 轨迹内逐轮 |
|---|---:|---:|---:|
| 自评 | 19.2% | 9.4% | **71.4%** |
| 独立 | 17.5% | 11.7% | **70.8%** |

轨迹内占七成——**有东西在动**。但独立口径下去掉轮次趋势后 lag-1 = **0.000**（p=1），
说明动的那部分不可预测。**"有变化"和"有状态"是两回事。**

### 0.3 闭环要成立的三个前提，防御线一个都没确证

| 前提 | ERGO 线 | 防御线 |
|---|---|---|
| 1. 执行器在**有效指标**上有权威 | 开局第一个实验：+0.425，p=6.39e-9 | **从来没测过**。自评 gate1 +0.0937（P 已证其量程 75% 是假阳性），独立 gate1 −0.0052 |
| 2. 早期观测对晚期有预测力 | — | **r ≈ 0**（0.1 节） |
| 3. 读出与被验证构念耦合且有量程 | `closeness` 满足 | 四候选全灭：自评（无效）/ 独立（无量程）/ 软 judge（后验塌缩，G2 三条全灭）/ 激活投影（非因果+不持久）；`goal-term recall` 有状态但与目标正交 |

**第 1 条最基础，而它从 Phase A 做到 Phase J 都没做过。** D1 就是补这一条。

## 二、A1：路线 A 的第一道门——危险度能不能只从攻击文本预测（零成本）

**类型**：CPU，秒级。**依赖**：无，**与 D1 并行**。

### 2.1 规格

新建 `scripts/analyze_attack_risk_predictability.py`（CPU-only，纯 numpy/scipy/sklearn）。

- **样本**：0.1 节那 255 条轨迹（全部非 `_indepjudge` 的 `rejudge_*` 臂，剔除前两轮插过
  提醒的轨迹），30 个攻击。
- **被预测量**：`late_y` = turns{3,4,5} 的均值，**自评与独立各跑一遍**。
- **特征（全部确定性、零 GPU，只用攻击层信息，不许用任何回复侧的量）**：
  `category` 的 one-hot（5 类：illegal / chemical_biological / harmful /
  harassment_bullying / cybercrime_intrusion）、`plain_query` 的词数与实词数、
  turn-1 `attacker_query` 的词数、问句目标词命中率（定义见
  `measurement_validity_plan.md` 2.3 节的停用词表）、`actor_name` 的 one-hot（若基数
  ≤ 8，否则丢弃并说明）。
- **模型**：ridge 回归（`alpha` 在训练折内用 5 折 CV 从 `[0.1, 1, 10, 100]` 选）。
  **不要上 TF-IDF 或任何高维文本特征**——只有 30 个攻击，必然过拟合。
- **评价**：**留一攻击法**（held-out 攻击的**全部**轨迹进测试折，30 折），报
  `R² = 1 − SSE/SST`（SST 相对全局均值），并给**按攻击 bootstrap 1000 次**的 95% CI。
- **两个参照必须并排列出**：(a) 全局均值（R²=0 的定义）；(b) **oracle 攻击均值**
  （0.1 节的 0.571 / 0.453）——这是文本预测的**天花板**。

### 2.2 闸门与判定

**闸门 G-A1-1**：oracle 攻击均值预测器复现 0.1 节的 R²（自评 0.571 / 独立 0.453，两位小数）。
对不上就停。

**预注册判定**（跑之前写下）：

| 留一攻击 R²（独立 judge 口径） | 裁决 |
|---|---|
| CI 下界 > 0 且点估计 ≥ 0.15 | 攻击文本能预测危险度 → 路线 A 可行，进 A2 |
| CI 下界 > 0 但点估计 < 0.15 | 弱可行 → 报给用户，由 Opus 决定值不值得进 A2 |
| CI 含 0 | **路线 A 也不成立**：危险度只有"事后按攻击聚合"才可预测，事前预测不出来 → 防御线只剩路线 B 与负结果 |

**预注册预期**：不预测。30 个攻击、5 个类别，样本非常小，**R² 为负是完全可能的结果**，
那也是一个干净的答案。

## 三、A2：跨轨迹预算分配的离线策略评价（❌ **已作废**——A1 在第一道门被否，见第九节）

**类型**：CPU，秒级，零 GPU。**依赖**：D1（判为"有权威"）**且** A1（判为可行）。

**这个任务要回答什么**：如果风险事前可预测、而且提醒确实有效，那真正可赢的问题就不是
"这条对话里什么时候提醒"，而是"**K 个提醒预算分给 N 条对话，给哪几条**"。这仍然是分配
问题、仍然做等代价比较，但它是**预测 + 静态分配，不是闭环控制，更不是 Koopman**——
文档与论文里必须这么写，不许包装成闭环。

### 3.1 规格

- **反事实对**：`phaseE_zero_control` 与 `phaseE_constant_remind` 的 16 条共同轨迹，
  每条都有"不防御"与"防御"两种结果。结果量用**独立 judge 的 `late_y`**
  （P 已判定它方向正确，且这一步不需要再花标注）；若 D1 已产出裁决标签，**并排再报一遍
  裁决口径**。
- **策略**：用 A1 的模型对每条轨迹的攻击算预测危险度，按预测值降序取前 K 条施加防御，
  其余不防御；`K ∈ {2, 4, 8}`（16 条里的 1/8、1/4、1/2）。
- **等代价对手**：同样的 K，但**随机选 K 条**（`default_rng(0)`，1000 次重复取分布）。
- **上界参照**：oracle 分配（按**真实**收益降序取前 K）。
- **判据**：`策略 − 随机` 的均值差，配对 bootstrap 10000 次，95% CI。

**闸门 G-A2-1**：16 条轨迹在两个臂里逐条对得上（`trajectory_id` 集合相同）；
K=16 时策略与随机必须**完全相同**（全选，退化检查）。

**预注册判定**：至少一个 K 上 `策略 − 随机` 的 95% CI 不含 0 且为正 → 路线 A 有正面证据，
报给用户由 Opus 写正式规格；全部 K 都跨零 → 路线 A 在现有数据上无法证实
（**n=16 很小，这时要报的是"功效不足"而不是"证否"**）。

## 四、B1（**已改写为诊断版**）：先测基线率抬不抬得起来

**为什么改写**：原来的理由是"截断可能低估有害内容"。D1 之后理由更硬——**基线率决定了这条线

|---:|---:|---:|
| **0.098（D1 实测）** | **444** | 148 |
| 0.20 | 199 | 66 |
| 0.30 | 120 | 40 |

### 12.1 为什么 LLM 闭环控制结构性地难——三条，都已被测量

1. **观测量在有效口径下近乎退化。** 独立 judge 91% 顶天花板、前两轮 98% 满分；软化成期望值后
   **95.67%** 的行落在原档位 ±0.02 内，而 sycophancy 线上同一修法是 **96%**——两种不同的标签
   几何、同一个失败模式（4B judge 在标签 token 上的后验是 one-hot 的）。
2. **可利用的方差在 episode 之间，不在 episode 之内。** 攻击身份留一法解释 **45–63%**，
   而前两轮观测对 late 的相关是 **−0.066 / +0.041**；且 A1 证明那 45–63% 从攻击文本本身
   **预测不出来**（LOAO R² −0.60 / −0.78）。
3. **执行器没有中间态。** 三个家族都试过：

   | 家族 | 实例 | 结果 |
   |---|---|---|
   | 离散文本插入 | 安全提醒 | 权威在噪声之下，测不出来（D1） |
   | 上下文手术 | ERGO reset | **整个替换状态**，116/116 输出逐字相同（G4） |
   | 连续扰动 | steering α 扫描 | dose-response 两次不过（p=0.0563 / 0.4535） |

   **要么动不了，要么把世界换掉，中间没有档位——而控制理论恰恰住在中间档位。**
   Koopman/MPC 假设一个持久状态被连续输入扰动；这三类执行器都不满足。

### 12.2 覆盖面（决定这套结论能不能立住的关键）

**3 个任务**（越狱防御 / 立场维持 / 分片数学）× **6 个读出候选**（自评硬标签、独立硬标签、
软 judge、激活投影、token 熵 ×2）× **3 个执行器家族**。单个失败叫运气不好，这个矩阵叫结构。

**最大的审稿风险**是"你只是挑了个坏设定"。唯一的防御是把**廉价识别坏设定的方法**本身作为
产出——即上面这张分层表加上第四节 4.0 的兑换率表。

### 12.3 若最终判断"需要一个正面的闭环结果才立得住"

按分层表，**唯一五层里有四层已经站住的设定**是：把 ERGO 的 reset 从**覆盖**改成**追加**
（`ergo_math_trajectory.py:114` 一行）。那样第 0 层（终点不再被单个动作决定）、第 1 层
（−0.448）、第 3 层（`closeness` 已过）全部满足，第 2 层需重测但大概率保留。
成本：一行改动 + 重跑 8 个臂（约半天 GPU）+ 重跑 RC 闸门。
**这是唯一值得花钱的地方，而不是回去修 Koopman。** 详见
[`ergo_multiturn_reliability_pilot.md`](ergo_multiturn_reliability_pilot.md) G4.5。
