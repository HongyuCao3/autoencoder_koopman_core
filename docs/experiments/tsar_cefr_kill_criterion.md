## 一、框架选择（H1 的 30 秒判据）

潜变量 $Z$ = 运行时状态 $\xi_t = (\ell_t, s_t)$ 在**扣掉开环臂已知的 (源级, 目标级, 步 $t$) 之后的剩余部分**；
$Y$ = 终点主量（TSAR 官方加权分）；$X$ = (源级, 目标级, $t$)。

闭环相对等代价开环的全部价值上界于 $I(Z; Y \mid X)$。这是 routing / capacity 类，**MI 上界框架适用**。

**本仓库已把这个探针做过三次，三次都判零**——这是本线设计的直接输入，不是背景：

| 线 | 探针形式 | 结果 |
|---|---|---|
| `defense` | 因果 oracle：所有按 $y$ 可测的策略的 in-sample 上确界 | **+0.0063，CI 跨 0**（40 条上 +0.0042 跨 0） |
| `constraint` | 日程可分性：算子上最优动作序列的种数 | **1 种** ⇒ argmax 与状态无关 |
| ERGO | 终点对早期状态的依赖 | **116/116 逐字相同** ⇒ 构造性为零 |

`tsar_cefr` 押的是**同一个量在这条线上不为零**，理由是任务族结构变了：动作直接写入下一步输入，
且过冲有代价。这个理由必须被上界探针**直接验证**，不能只由辨识出的算子间接证明——见 D-2.5。

## 二·五、D-2.5 的策略类与估计量（2026-09-14 用户签字，**树落盘之前**）

> **为什么要补这一节**：D-2.5 原文只写「所有按 $\xi_t$ 可测的策略的 in-sample 上确界 − `dp_path`」。
> $\ell$ 是连续量，深度 4 的树里每个节点的状态都唯一——**不加限制的上确界会退化成全知最优路径**
> （每个节点各选各的），那不是上界。`defense` 线的因果 oracle 从来不是这么算的：它把读出**分箱**、
> 策略**跨轨迹共享**、并用**留一**的数作判据。本节把那套做法搬过来并签死。
> **用户裁决 2026-09-14：「策略类照 defense 先例签」。**

**(1) 状态分箱**。箱定义在**到目标的距离** $d_t=\ell_t-\ell^\star$ 上（$\ell^\star$ = 目标级的整数编码）：

| 箱 | 判据 |
|---|---|
| 远 | $d_t \ge 1.0$ |
| 近 | $0.5 \le d_t < 1.0$ |
| 到位 | $d_t < 0.5$ |

**3 箱为判据、4 箱为次要**（次要把「到位」拆成 $0 \le d_t < 0.5$ 与**过冲** $d_t < 0$），
与 `defense` 的 3 箱/4 箱结构一致。**箱界不是从数据里选的**：它逐字等于计划 §5.4 里
`greedy_reactive` 的那三条规则（「离目标 ≥ 1 级 → 降一级；0.5–1 级 → 降半级；≤ 0.5 级 → 保持」），
所以上确界与 `greedy_reactive` 的差有直接含义——**任何箱可测策略能比那条手写规则好多少**。

**(2) 策略类**。$\pi:(\text{箱}) \to \text{动作}$，**步不变**、**跨格共享**、按目标级各拟一份。
$4^3=64$ 条策略/目标级（次要口径 $4^4=256$），**可穷举，不需要近似搜索**。
步不变是预注册的限制，不是算力妥协：`greedy_reactive` 本身就是步不变的，
而允许逐步不同会把策略数抬到 $4^{12}$ 并让上确界重新向全知退化。

**(3) 目标量**。计划 §5.4 的主量：**终点（深度 4）的 CEFR RMSE**，在**整数编码**级上算，
用 `level_official`。保义按计划作**准入阈值不作加权项**——**该阈值尚未签**（计划说「在 trial 20 源上定」），
所以本闸门先报**不带保义门**的主量，带门的版本在阈值签字后同址补，**两个都报，不择优**。

**(4) 判据（签死）**。

$$\text{D-2.5 主量} \;=\; V(\text{最优箱可测策略}) \;-\; V(\text{最优开环策略})$$

其中**开环策略**只看 $X=(\text{源级},\text{目标级},\text{步})$、不看运行时 $\ell_t$——
这就是 `defense` 先例里的「最优固定日程」。**两侧都用留一源（leave-one-source-out）**：
在 99 个源上选最优策略、在留出的那个源上评，对 100 个源取平均。
**留一的数是判据**；in-sample 的数**同址报、不判**（先例：in-sample 在 16 条上 +0.0469 ★、
在 40 条上 +0.0042 跨 0，**高估 11 倍**）。按 `source_id` 自举 2000 次（计划 §5.4 的抽次）。

**CI 含 0 → D-2.5 触发 → 关闭 `tsar_cefr`**（死亡条件 §二 原文，未改）。
本臂自算 MDE 同址报，但**不进入判据**——D-2.5 的原文只写了 CI，不许事后加一个更宽的门。

**(5) 这一条把 `dp_path` 从闸门里解耦出来。** 被减数是**最优开环策略**，从树里精确算得；
`dp_path` 退回为该开环类里一个**具名的已发表实例**。因为最优开环 $\ge$ `dp_path`，
**这个被减数比原文更严**，上界更难过。`dp_path` 仍是 Table 2（GPU-2）的义务，
它的三处不匹配见 [`tsar_cefr_results.md`](tsar_cefr_results.md) §「`dp_path` 的来源已查清」，
**仍待裁决，但不再阻塞 D-2.5**。

**(6) 视界**。树深 4 = 计划 §5.4 的 MPC 视界。**D-2.5 在 H=4 上判**，
并且这是**保守方向**：$H<6$ 的上界是 6 步上界的下界，判零即可关线。

## 三、相对计划 §2.2 的四处修订与依据

**(1) 新增 D-2.5 —— D-1…D-5 原本没有一条是直接的上界探针。**
D-3 与 D-4 都在**辨识出的算子上**算，中间隔着一层拟合；算子拟合不好会假阴，拟合虚构了结构会假阳。
`defense` 线的因果 oracle 是不经过算子、直接在数据上的上确界，本仓库已有实现
（[`adaptivity_ceiling_results.md`](adaptivity_ceiling_results.md)）。把它挪到 Phase 3 之前，
用 GPU-1 已有的行算，零 GPU。

**它必须在全量 N 上算，试点会骗**：同一个 in-sample 上界在 16 条试点上是 **+0.0469 ★**、
在 40 条上是 **+0.0042（跨 0）**（[`../LEDGER.md`](../LEDGER.md) §「同址记一条方法教训」）。

**(2) D-3 的可分性计数限定在固定目标级内 —— 原措辞会假通过。**
计划 §5.2 写「对每个 (源级, 目标级) 求最优序列；不同起点的最优序列 ≥ 2 种」。若「不同起点」
跨目标级轴计数，那部分差异**开环臂也拿得到**（目标级是 $X$ 的一部分，`dp_path` 按它选路径）。
可分性只有在**固定 (源级, 目标级) 内、由运行时 $\ell_t$ 造成**时才是闭环独有的。

**(3) D-4 加 setting switch —— H3 的两个闸门原本只有一半。**
计划有 metric switch（FKGL 副读出方向一致率、次量「到达 ±0.5 的首步数」），没有 setting switch。
补：模拟层结果在**只留 B1** 与**只留 A2** 两个子设定内各复算一次，符号一致才算过。模拟层零成本。

**(4) 新增 D-0 —— 裁决 4 的后果原本没有关闭条款。**
饱和探针阳性时计划写「换更小模型或收紧口径」，没写换几次。按「同一仪器只修一次」的同构：
被控模型是 setting 不是仪器，允许换，但**只换一次**。

**未改的三条**：D-2、D-5 与计划 §2.2 逐字相同（D-1 于 2026-09-14 修订，见下 (5)），
覆盖面与三条已关闭线的失效模式一一对应。

**(5) D-1 ①b 于 2026-09-14 修订：100% → 方向正确率 ≥ 0.85 且配对 Δ$\ell$ 均值 CI 上界 < 0。**
用户签字，依据 [`../tsar_cefr_gt1_closure_review_2026-09-14.md`](../tsar_cefr_gt1_closure_review_2026-09-14.md)，
完整的四条留痕（含「这是事后放宽」）写在
[`tsar_cefr_results.md`](tsar_cefr_results.md) §「判据修订记录（2026-09-14）」。
一句话理由：原阈值要求 TSAR 官方评测器零误差，而它的发表精度是 F1 0.89 / RMSE 0.34，
在 40 对上大概率至少错一对——**这条判据检验的是一台不存在的仪器**。
0.85 由发表精度推出，不由本次数据反推；实测 0.95 与 CI 上界 −0.675 都不是踩线过。
**D-1 ② 未改**，仍由 GPU-1 的开环臂判。

  借用权威：控制论的定点调节（设定点跟踪 + 过冲惩罚）。`recorded_at: 2026-09-13`（非 post_hoc）。
