## 1. 目标版式

用户已定：**左 1/4 = 整体逻辑（自上而下的白色文字框）；右 3/4 = 模块内部结构，拼成矩形。**

```
┌───────────┬──────────────────────────────────────────────┐
│ 左栏 3.4cm│ 右栏 10.4cm                                   │
│ 闭环流程   │ ┌────────────┬───────────────────────────────┐ │
│ 白框 ×6   │ │ A 有限记忆   │ B 命令条件化 Koopman 模型        │ │  上行 3.3cm
│ 自上而下   │ │ 状态 (§3.2) │   E_φ → ξ → Kξ+Bc+b → D_ψ → ŷ │ │
│ 带 A–D 色点│ ├────────────┴──────────┬────────────────────┤ │
│ 回环箭头   │ │ C 离线训练 (§3.3)      │ D 预测式测试时控制   │ │  下行 3.3cm
│           │ │   三项损失             │   (§3.4) 候选滚动+argmin│ │
│           │ └───────────────────────┴────────────────────┘ │
└───────────┴──────────────────────────────────────────────┘
  总画布 14.0cm × 7.0cm（= ICLR \textwidth 5.5in，1:1 不缩放，字号即最终字号）
```

版式决定的理由：
- 画布按 `\textwidth = 5.5in ≈ 13.97cm` 原尺寸画，`\includegraphics[width=\textwidth]` 时不缩放，`\scriptsize`(7pt) 就是最终 7pt，避免"画布上好看、缩进论文后 5pt"的老问题。
- 右栏不用均匀 2×2：模块 A 内容少（一条窗口 + 一张小图）、模块 B 是六节点横向链条要宽度，所以上行按 1:2 分；下行 C、D 各半。若 B 仍挤，允许 A:B = 3:7。
- 阅读顺序：左栏自上而下 = 一次交互的时间顺序；右栏 A→B→C→D = §3.2→§3.2→§3.3→§3.4 的章节顺序。左栏每个白框右上角一个小色点（A/B/C/D 的颜色），指向右栏对应模块，这就是"整体逻辑 ↔ 模块内部"的连接方式，不画跨栏箭头（跨栏箭头在 1/4 : 3/4 的版式里一定和别的线打架）。

## 1.5 视觉语法：每个数学对象对应唯一一种图元（右栏的硬规范）

先说为什么要这一节：同事图的问题不只是记号，而是**每个模块都是"标题 + 一句话"的文字框**，读者看不到 Koopman 预测器里面有什么。要让图"说人话"，规则只有一条——**§3 里每一类数学对象，在图上都有且只有一种画法，并且画法要能让读者从形状看出维度和合法运算。** 神经网络就画成带神经元的梯形，向量就画成有格子的竖条，矩阵就画成有格子的方块，标量就是一个格子。文字只剩 ≤4 词的标签。

### 1.5.1 图元词表（所有模块只能用这张表；新图元由 Opus 在步骤 0 加进 `kompas_style.tex`，Sonnet 不得自造）

| §3 里的对象 | 图元 | 尺寸 / 标注规则 | 颜色 | 宏（已有 / 步骤 0 新增） |
|---|---|---|---|---|

| 记忆向量 $s_t, \hat s_{t+1}, s_{t+1}\in\mathbb{R}^{L+1}$ | **竖向格子列**，$L{+}1=4$ 格，每格内写 $y_t, y_{t-1}, \dots$（或只在首末格写） | 右侧花括号标 $L{+}1$ | token 分类色（`tok1..tok4`，表示"观测数据"） | 已有 `\TokColV` |

| 线性特例 $E_\phi=D_\psi=\mathrm{id}$ | **虚线直通旁路箭头**跨过梯形上方，标 `id` | 只出现在模块 B | 灰虚线 | 新增 `\IdBypass{from}{to}` |
| 仿射一步 $\hat\xi_{t+1}=K\xi_t+Bc_t+b$ | **分块矩阵等式**：`[3×1] = [3×3][3×1] + [3×1][1×1] + [3×1]`，用真实格子块拼出，运算符 $=,+$ 用 `mathlab` | 这是模块 B 的中心，宽约 3.2cm | 各块按上面各自颜色 | 由上面的块宏拼装 |

| 验证器 $V$ | 小尺子 glyph（一条带刻度的横线）+ $V$ | — | 黑 | 新增 `\RulerV{pos}` |

| $H$ 步隐空间滚动 | **横向一排 $H=3$ 个隐向量列**，列间小 $K$ 块与 `+Bc+b` 标签，颜色随 $h$ 变浅 | 下方花括号标 $h=1\ldots H$ | 蓝渐变 | `\LatColV` ×3 + `\MatBlock` |
| 预测轨迹 vs 目标 | **迷你坐标图**：横轴 $h$、纵轴 $\hat y$、绿色虚线水平线 $r$；三条折线 | 轴标签只写 $h$、$\hat y$ | 三条线 = 三候选色；越过 $r$ 的那条红 | 新增 `\MiniAxes{pos}{w}{h}` + 手画折线 |
| 代价 $\hat J_t(c)$ | **横条**，长度 ∝ 偏离 | 三条并排 | 与候选同色 | 手画 `\fill` |
| $\arg\min$ / $c_t^\star$ | `ours` 蓝实心箭头指向最短横条，箭头旁一个 `ours` 色单格写 $c_t^\star$ | — | `ours` | `\ScalarCell` |
| 时间推进 / 回环 | 箭头本身；不写 "then / next" 之类动词 | — | 黑 | `flow` |

三条派生规则：
1. **每个张量必带形状标注**（花括号 + 维度符号），但同一维度在同一模块只标一次，避免括号堆叠。
2. **箭头上写运算，不写动词**：允许的箭头标签只有 $E_\phi$、$D_\psi$、$C$、$K$、$K^h$、$\mathcal{P}$、$V$、$p_\theta$，禁止 "encode / predict / decode / update"。
3. **文字节点配额**：右栏每个模块里，纯文字节点（不含图元的框）数量为 **0**；`minicap` 标签 ≤ 3 条、每条 ≤ 4 词。Opus 合并前数一遍，超了退回。

### 1.5.2 左栏的豁免与折中

左栏按用户要求是白色文字框，保留文字框形式；但每个框的**左侧**放一个 0.35cm 的微型图元当"图标"（框 1：单格 $r$；框 2：$\mathcal{P}$ 小矩形；框 3：`\FrozenLLM` 缩小版；框 4：尺子；框 5：4 格竖列；框 6：3 格蓝列 + 星），让左栏与右栏共用同一套视觉词汇，读者从左栏的图标就能认出右栏的模块。字号与文字规格不变。

## 3. 分步执行（每步：Opus 生成 → 渲染 PNG → 用户审核 → 记账 → commit → 停）

固定审核闸门（每步都跑，写进 FIG_STATE）：
- G1 编译通过，PNG 渲染并**由 Opus 自己看过**（Read 图片），不许交未看过的图。
- G2 **符号审计**：`python paper/tools/fig_symbol_audit.py <fragment>.tex` 全部命中 `02_method.tex`；零新符号。
- G3 无重叠、箭头端点落在节点边框上、无 `\tiny`（最小 `\scriptsize`）。
- G4 文字预算：每个节点 ≤ 4 个英文词 + 一行公式；图内不出现完整句子、不出现引号包着的例句。
- G5 色彩语义：蓝 = 结构（网络/隐变量）、`ours` 蓝 = KOMPAS 自己的贡献（选择器、$c_t^\*$）、绿 = 达标/好、红 = 过冲/坏；A–D 四个模块色只用在角标和左栏色点上，不用于内容。
- G6 数字：图内只允许出现例子数字（句长 11 / 20 / L / H），不出现任何实验结果数字（Rule 21）。
- G7 **图元规范**（§1.5）：右栏纯文字节点数 = 0；每个张量有形状标注；每个网络有神经元；每个箭头标签在 §1.5.1 派生规则 2 的白名单内；Opus 用 `grep -cE 'node\[[^]]*\]\s*\{[^$]*\}'` 粗数纯文字节点，再看图确认。不过 G7 不进人审。

用户审核结论三种：`approved` / `revise:<具体项>` / `redo`。`revise` 在同一步内迭代（版本号 +1）；`redo` 回到该步的规格重写。
