## 0. 现状分析：同事的 `figs/method.png` 哪里要改

先说结论：**同事图的骨架（顶部闭环 + 底部控制器）是对的，但它画的是一篇"旧记号、黑箱预测器"的论文；现在的 §3 已经换了记号并且把预测器拆成了四个有公式的模块，图必须跟上。**

### 0.1 图里有什么

| 区域 | 内容 | 判断 |
|---|---|---|
| 顶行五个框 | Task Input (x) → Prompt/Context (p_t) → LLM (frozen) → Model Output (y_t) → Verifier V, s_t = V(y_t) | 流程正确，记号全错（见 0.2） |
| 底部大框 "Koopman-based Predictive Controller" | 从右到左：Current State s_t → Trajectory Prediction ŝ = F̂(s,u)（附小折线图）→ Candidate Prompt Interventions U={u^(1..3)} → Plan & Select u* = argmin J → Selected Prompt Intervention u_t* | 阅读方向从右到左，与顶行相反；预测器是一个黑箱 F̂ |
| 例子 | 句长目标 20、当前 11、误差 9；三条候选提示词原文 | 数字例子好，可保留；整句引文太重 |
| 小折线图 | 三条候选的预测轨迹 vs Target 20 | **全图最好的一个元素**，要保留并升级 |
| 品牌 logo | OpenAI / Meta 图标 | 删除（商标；与内容无关） |
| 格式 | 1.75 MB 光栅 PNG，文字缩放后发虚 | 换成 TikZ 矢量 PDF |

### 0.2 记号冲突（必须全部改）

| 同事图 | `02_method.tex` 现行记号 | 含义 |
|---|---|---|
| $y_t$ = LLM 输出文本 | $o_{t+1}$ | 生成的文本 |
| $s_t = V(y_t)$ | $y_{t+1} = V(o_{t+1})$ | 验证器读出的标量属性 |
| $s_t = [\text{length}: 11]$ | $s_t = [y_t, y_{t-1}, \dots, y_{t-L}]^\top \in \mathbb{R}^{L+1}$ | 有限记忆状态（图里完全没画出"窗口"） |
| $z^\*$ | $r$ | 目标属性值 |
| $u \in U$ 候选提示词 | $c \in \mathcal{C}_t$ 候选**命令**（数值）；$u_t = \mathcal{P}(x,\mathcal{H}_t,c_t)$ | 命令与提示词是两层 |
| $p_t$ | $u_t$（提示）、$\mathcal{H}_t$（历史） | — |
| $\hat s_{t+1} = \hat F(s_t,u)$ | $\xi_t = E_\phi(s_t)$；$\hat\xi_{t+1} = K\xi_t + Bc_t + b$；$\hat s_{t+1} = D_\psi(\hat\xi_{t+1})$；$\hat y = C\hat s$ | 预测器内部结构 |
| $J(s_{t+1:H}, z^\*)$ | $\hat J_t(c) = \sum_{h=1}^H w_h \lvert \hat y_{t+h\mid t}(c) - r\rvert^2$ | 代价 |

### 0.3 缺失的模块

§3 有五个小节，图只覆盖了 §3.1（闭环）和 §3.4 的一半（选择）。缺：
- §3.2 **有限记忆状态**：窗口、选择行 $C$、"同一句长可能在变长也可能在变短"的双向例子（contract `ex_1`，图是它的天然家）。
- §3.2 **命令条件化 Koopman 模型**：编码器 / 仿射隐空间 / 解码器；命令 $c_t$ 作为显式输入列 $B$；**线性特例 $E_\phi = D_\psi = \mathrm{id}$**（裁决 D2，主表 Ours 行就是这个特例，图上必须标出来）。
- §3.3 **离线训练**：三项损失 $\mathcal{L}_{\mathrm{rec}}, \mathcal{L}_{\mathrm{lin}}, \mathcal{L}_{\mathrm{pred}}$。
- §3.4 的另一半：**隐空间 $H$ 步滚动不调 LLM**（$K^h$ 闭式）、执行首步后重规划（receding horizon）。
- §3.5 误差界：**不画**，放图注一句（见 §6 待裁决 Q3）。

## 1. 目标版式

用户已定：**左 1/4 = 整体逻辑（自上而下的白色文字框）；右 3/4 = 模块内部结构，拼成矩形。**

```
┌───────────┬──────────────────────────────────────────────┐
│ 左栏 3.4cm│ 右栏 10.4cm                                   │
│ 闭环流程   │ ┌────────────┬───────────────────────────────┐ │
│ 白框 ×6   │ │ A 有限记忆   │ B 命令条件化 Koopman 模型        │ │  上行 3.3cm
│ 自上而下   │ │ 状态 (§3.2) │   E_φ → ξ → Kξ+Bc+b → D_ψ → ŷ │ │
│ 带 A–D 色点│ ├────────────┴──────────┬────────────────────┤ │
│ 回环箭头   │ │ C 离线训练 (§3.3)      │ D 预测式测试时控制   │ │  下行 3.3cm
│           │ │   三项损失             │   (§3.4) 候选滚动+argmin│ │
│           │ └───────────────────────┴────────────────────┘ │
└───────────┴──────────────────────────────────────────────┘
  总画布 14.0cm × 7.0cm（= ICLR \textwidth 5.5in，1:1 不缩放，字号即最终字号）
```

版式决定的理由：
- 画布按 `\textwidth = 5.5in ≈ 13.97cm` 原尺寸画，`\includegraphics[width=\textwidth]` 时不缩放，`\scriptsize`(7pt) 就是最终 7pt，避免"画布上好看、缩进论文后 5pt"的老问题。
- 右栏不用均匀 2×2：模块 A 内容少（一条窗口 + 一张小图）、模块 B 是六节点横向链条要宽度，所以上行按 1:2 分；下行 C、D 各半。若 B 仍挤，允许 A:B = 3:7。
- 阅读顺序：左栏自上而下 = 一次交互的时间顺序；右栏 A→B→C→D = §3.2→§3.2→§3.3→§3.4 的章节顺序。左栏每个白框右上角一个小色点（A/B/C/D 的颜色），指向右栏对应模块，这就是"整体逻辑 ↔ 模块内部"的连接方式，不画跨栏箭头（跨栏箭头在 1/4 : 3/4 的版式里一定和别的线打架）。

## 3. 分步执行（每步：Opus 生成 → 渲染 PNG → 用户审核 → 记账 → commit → 停）

固定审核闸门（每步都跑，写进 FIG_STATE）：
- G1 编译通过，PNG 渲染并**由 Opus 自己看过**（Read 图片），不许交未看过的图。
- G2 **符号审计**：`python paper/tools/fig_symbol_audit.py <fragment>.tex` 全部命中 `02_method.tex`；零新符号。
- G3 无重叠、箭头端点落在节点边框上、无 `\tiny`（最小 `\scriptsize`）。
- G4 文字预算：每个节点 ≤ 4 个英文词 + 一行公式；图内不出现完整句子、不出现引号包着的例句。
- G5 色彩语义：蓝 = 结构（网络/隐变量）、`ours` 蓝 = KOMPAS 自己的贡献（选择器、$c_t^\*$）、绿 = 达标/好、红 = 过冲/坏；A–D 四个模块色只用在角标和左栏色点上，不用于内容。
- G6 数字：图内只允许出现例子数字（句长 11 / 20 / L / H），不出现任何实验结果数字（Rule 21）。

用户审核结论三种：`approved` / `revise:<具体项>` / `redo`。`revise` 在同一步内迭代（版本号 +1）；`redo` 回到该步的规格重写。

### 3.2 步骤 2 — 右栏四个模块（可并行派 4 个 Sonnet；Opus 审、合）

每个模块一个独立片段，局部坐标原点左下，用 `build.sh modX_*` 单独预览。四个模块的**输入契约**相同：`kompas_style.tex` + `symbols.tex` + 目标尺寸 + 下面的规格 + `02_method.tex` 对应小节原文。Sonnet 只写片段、跑 `build.sh` 与 `fig_symbol_audit.py`、返回 PNG 路径；Opus 看图后决定接受或让同一 Sonnet 改。**四个模块可以一起交用户审（一次审核），也可以逐个审；默认一起审，因为用户审的是"四张小图是否说清各自机制"，相互独立。**

**2a `modA_memory.tex`（§3.2 前半；尺寸 3.4cm × 3.3cm）**
- 顶部：横向 $L+1$ 格 token 条，格内写 $y_t, y_{t-1}, \dots, y_{t-L}$（$L{+}1 = 4$ 格即可），下方花括号标 $L{+}1$；左侧一个选择行 $C=[1,0,\dots,0]$ 用一条细箭头从首格引出到 $y_t$，表达 $y_t = C s_t$。
- 底部：**双向例子小图**（contract `ex_1`）——一张 2.4cm 宽的迷你折线：两条轨迹在 $t$ 时刻交于同一点（句长 11），一条来自上方下降、一条来自下方上升；箭头分别继续向下 / 向上；标签 `same $y_t$, opposite trend`（≤4 词）。这张小图就是"为什么要记忆"的全部论证。
- 角标 `A  Finite-memory state`。

**2b `modB_koopman.tex`（§3.2 后半，式 koopman_model；尺寸 7.0cm × 3.3cm）**
- 横向链：$s_t$（竖向 $L{+}1$ 格）→ $E_\phi$（`\EncNet` 带神经元的梯形）→ $\xi_t$（竖向 $d_\xi$ 格隐向量，蓝）→ **仿射块**（方框，内写 $K\xi_t + Bc_t + b$）→ $\hat\xi_{t+1}$ → $D_\psi$（`\DecNet`）→ $\hat s_{t+1}$ → 细箭头 $C$ → $\hat y_{t+1}$。
- 命令 $c_t$ 从仿射块**上方**用 `ours` 色箭头进入，箭头上标 $B$；这是"命令是显式输入列"的画法，是全图最重要的一个箭头。
- 仿射块下方一行 `minicap`：`linear special case: $E_\phi = D_\psi = \mathrm{id}$`（裁决 D2；这一行必须有）。
- 角标 `B  Command-conditioned Koopman model`。

**2c `modC_training.tex`（§3.3，式 training_objective；尺寸 5.2cm × 3.3cm）**
- 画成一张**交换图**而不是再画一遍网络：上排 $s_t \xrightarrow{E_\phi} \xi_t \xrightarrow{K\cdot + Bc_t + b} q_t \xrightarrow{D_\psi} D_\psi(q_t)$；下排 $s_{t+1} \xrightarrow{E_\phi} \xi_{t+1}$；另加 $s_t \to D_\psi(E_\phi(s_t))$ 的短支路。
- 三条**红色双向虚线**标三项损失：$\mathcal{L}_{\mathrm{rec}}$ 连 $s_t$ 与 $D_\psi(E_\phi(s_t))$；$\mathcal{L}_{\mathrm{lin}}$ 连 $\xi_{t+1}$ 与 $q_t$；$\mathcal{L}_{\mathrm{pred}}$ 连 $s_{t+1}$ 与 $D_\psi(q_t)$。
- 底部一行 `minicap`：`offline, $\theta$ frozen; updates $(\phi,\psi,K,B,b)$`。
- 角标 `C  Offline learning`。

**2d `modD_control.tex`（§3.4，式 rollout / closed_form / selection；尺寸 5.2cm × 3.3cm）**
- 左：候选集 $\mathcal{C}_t=\{c^{(1)},c^{(2)},c^{(3)}\}$ 三个小圆点（三色：蓝 / 红 / 绿）。
- 中：**升级版的同事小折线图**——横轴 $h = 1\ldots H$，纵轴 $\hat y_{t+h\mid t}(c)$，虚线水平线 $r$（标 `target $r$`）；三条候选轨迹，颜色与候选点一致；红色那条明显**过冲**越过 $r$（呼应 `fx_1` 过冲），绿色贴近 $r$，蓝色不足。坐标轴标签只写 $h$ 与 $\hat y$。图旁一行 `minicap`：`latent rollout $K^h\xi_t + \sum_j K^j(Bc+b)$, no LLM call`。
- 右：三根短横条 $\hat J_t(c^{(i)})$（长度与轨迹偏离一致，绿最短），`ours` 色箭头指向最短那根，标 $c_t^\* = \arg\min$。
- 底部：小箭头 `execute $u_t$, observe $y_{t+1}$, replan`（receding horizon 的三词版）。
- 角标 `D  Predictive test-time control`。

审核要点：每张小图遮住所有文字，机制是否还能看出来（窗口 / 显式命令列 / 三条损失 / 过冲被选掉）；四张图的符号是否与 §3 一致（G2 脚本已跑，但用户再扫一眼公式）。

### 3.3 步骤 3 — 右面板拼接 `right_panel.tex`（Opus 亲自）

- 只做定位：`\begin{scope}[shift={(x,y)}] \input{modA_memory} \end{scope}` ×4；四块外框用步骤 0 新增的 `panel` 样式（白底、`black!40` 细实线、圆角），外框间距 0.25cm；角标用 `tag` 样式（改 `font=\bfseries\scriptsize`），填四个模块色。
- 面板顶部不加大标题（整图标题由图注承担）。
- 跨模块只画**两条**关系线：A 的 $s_t$ → B 的入口（`s_t` 复用）；B 的 $\hat y$ → D 的折线图（预测器供给控制器）。C 与 B 之间不画线，用 C 角标下的 `trains B` 三个字表达。若两条线与内容碰撞，改为在 B、D 入口写 `from A` / `from B` 的 `minicap`，宁可不画线。

### 3.4 步骤 4 — master 与接入论文（Opus 亲自）
