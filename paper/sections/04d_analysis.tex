\subsection{From Prediction Quality to Control Quality}
\label{sec:exp_analysis}

Prediction accuracy matters for control only when it helps select a better command. The selection bound in \S\ref{sec:prediction_control_bound} formalizes this link: if each candidate’s predicted cost differs from its realized cost by at most \(\delta_J\), the selected command’s realized cost is at most \(2\delta_J\) above the best realized cost. This is a theoretical guarantee for one comparison at a single step, with each candidate held for \(H\) steps; it does not describe the replanned closed loop.

Candidate evaluation requires one linear propagation and a readout using the closed-form rollout in \S\ref{sec:control_method}, so it adds no queries to the target model. Because the transition is affine and the command enters through a scalar column, the \(h\)-step lookahead reduces to a matrix power.

We also compared the closed-loop controller with the best fixed schedule under the same instruction budget on Defense, Constraint, and CEFR (Appendix~\ref{app:A4_equal_cost}). The controller tied on two tasks and performed worse on Defense. On these tasks, the instruction itself shifted reading by 0.12–0.14, while rescheduling the same budget changed it by at most 0.03.

Finally, on four of the seven modeling columns, the applied command is an exact affine function of the memory state. In those cases, the prediction design cannot identify an independent command effect. For the other three columns, the estimated command effects all have intervals containing zero (Appendix~\ref{app:A7_command_channel}). This limitation reflects how the trajectories were collected, rather than a finding about the controller.
Taken together, the bound connects prediction error to command selection at a single step, and candidate evaluation requires no additional target-model queries. The equal-budget and command-effect checks show where the predictive gains studied in RQ1 may not carry over to the control gains studied in RQ2.
