\section{Introduction}
\label{sec:intro}

Multi-turn interaction turns a frozen language model's reply attributes into a trajectory, and that trajectory drifts turn over turn. What a model writes in recent turns carries into what it writes next, so reply attributes carry inertia rather than being drawn fresh each turn.
% CITE: li2024instability, driftnomore2025, attractorstates2025
One concrete instance is a rewrite pushed past the level it was aiming for. One candidate driver, among others, is that an instruction given once competes with everything said in every turn that follows.
% CITE: li2024instability, driftnomore2025, attractorstates2025

\textbf{Wrong interface.} Every existing controller acts inside the network, needing white-box access at every token. \uline{The lever a deployment holds is one instruction per turn against a black-box API.} \textbf{Stateless and open loop.} Existing prompt-level interventions include a system prompt written once, a reminder on a fixed schedule, and a per-turn classifier template. \uline{None of them predicts what the next instruction will do, so each overshoots or undershoots the desired attribute.} \textbf{No usable dynamics model.} A control-theoretic framing of prompting exists. \uline{No such framing turns one instruction into a predicted next-turn attribute.}

The quantity a controller cares about is a property of a whole reply, not of any single token inside it. A verifier that scores a reply runs once the reply is complete, never partway through generation. This complete-reply scoring rule makes the natural clock tick one exchange, not one token. Intervening at the token level needs access inside the network, while intervening at the interaction level needs only the ability to change the next prompt. Controlling a room's temperature needs no model of each air molecule, and controlling a reply's attribute needs no model of each token.

A predictor that takes one exchange as its step needs three properties together. It must admit that a frozen model can respond to an instruction in a nonlinear way. It must keep the step from one turn's state to the next linear, so a horizon of candidates becomes one matrix power rather than a new generation each time. It must keep the command an explicit, readable channel, not a hidden target for text regression. A recurrent sequence model admits the nonlinearity but gives up the linear step and the readable command. A per-turn Markov rule keeps the step linear but gives up the other two. We call the minimal structure meeting all three clauses \textbf{KO}opman dyna\textbf{M}ics modeling and \textbf{P}redictive control of \textbf{A}ttributes at the prompt \textbf{S}tep, or \textbf{KOMPAS}.
