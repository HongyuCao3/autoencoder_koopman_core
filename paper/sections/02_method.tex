\section{Method}

We formulate multi-turn attribute tracking as feedback control over
the observable attributes of a frozen LLM.
Figure~\ref{fig:placeholder} shows four pipeline stages, from a
finite-memory state built out of recent attribute readings to a
command-conditioned latent prediction of the next reading. A scoring
step ranks candidate commands, and execution of the chosen command is
followed by replanning. The LLM parameters remain fixed throughout;
only the external dynamics model is learned offline.

\subsection{Finite-Memory Interaction State}
\label{sec:memory_state}

For example, the same sentence length can occur while successive
revisions are becoming longer or while they are becoming shorter. A
single reading is therefore consistent with two opposite trends, so a
memoryless rule issues the same command in both cases even when the
next step differs. \textbf{Why a Verifier's Reading.} A window over past
readings is the standard fix for a partially observed system, so the
open question is which quantity gets windowed rather than whether to
window at all. A black-box caller obtains only a verifier's reading of
a finished reply, never a hidden activation, and the control objective
is stated in terms of that same reading. \uline{The state is built only
from what a verifier can read off a finished reply, the one signal
available to a black-box caller.}

Stacking the last several readings exposes both the current level and
its recent trend, closing the gap the opening example illustrates. We
represent the interaction using a finite window of attribute
observations,
\begin{equation}
    s_t=
    \begin{bmatrix}
        y_t & y_{t-1} & \cdots & y_{t-L}
    \end{bmatrix}^{\top}
    \in\mathbb{R}^{L+1},
    \qquad
    y_t=C s_t,
    \label{eq:memory_state}
\end{equation}
Here $y_t$ is the measured attribute at step $t$
(Section~\ref{sec:problem_modeling}), $L\geq 1$ is the number of
previous observations retained, and $C=[1,0,\ldots,0]$ selects the
current attribute from the stack. The vector $s_t$ is the memory state
used throughout the rest of the paper.
A short window of recent readings is assumed to carry enough of the
conversation to predict the next reading. It is an approximation to the
information needed for prediction, not an exact reconstruction of the
full dialogue state.

This memory state requires no access to hidden activations, only the
sequence of past verifier readings. It is what the operator introduced
next takes as its input.

\subsection{Command-Conditioned Koopman Operator}
\label{sec:koopman_operator}

\textbf{Why a Natural-Language Instruction Can Carry a Command
Coordinate.} An affine input column in a lifted space is standard
control machinery, so the open question is whether a natural-language
instruction can carry a scalar command coordinate at all. It can,
because the prompting protocol builds every prompt from that same
coordinate rather than from unconstrained text. The coordinate is
therefore a property of the protocol generating the instruction, not of
the instruction's surface wording. \uline{An instruction carries a
command coordinate only because the protocol generating it is built
from that coordinate in the first place.}

We make this concrete with a command-conditioned prompting protocol
\begin{equation}
    u_t=\mathcal{P}(x,\mathcal{H}_t,c_t),
    \qquad
    c_t\in\mathcal{C}\subseteq\mathbb{R},
    \label{eq:prompt_protocol}
\end{equation}
Here $\mathcal{H}_t$ is the dialogue history from
Section~\ref{sec:problem_modeling}. $\mathcal{P}$ constructs a prompt
from a numerical command $c_t$ and that history, and $\mathcal{C}$ is
the range of admissible commands from which every candidate is later
drawn.

Before approximating anything, the population object is the conditional
expectation of an observable one step ahead, given the state and the
command. Define the command-conditioned Koopman operator acting on an
observable $f$ by
\begin{equation}
    (\mathcal{K}_{c}f)(s)
    =
    \mathbb{E}\!\left[
        f(s_{t+1})
        \mid s_t=s,\,c_t=c
    \right].
    \label{eq:koopman_operator}
\end{equation}
Here $\mathcal{K}_{c}$ is the command-conditioned Koopman operator on
observables, and any learned model below is a finite-dimensional
approximation of it. The operator is linear in $f$, although the
underlying prompt-response dynamics can be nonlinear.

Approximating this operator in a learned, low-dimensional observable
space needs a map into that space, an affine step inside it, and a map
back out. We use an encoder $E_{\phi}$ and a decoder $D_{\psi}$:
\begin{equation}
    \begin{aligned}
        \xi_t
        &= E_{\phi}(s_t),
        & \xi_t &\in\mathbb{R}^{d_{\xi}},\\
        \widehat{\xi}_{t+1}
        &= K\xi_t+B c_t+b,\\
        \widehat{s}_{t+1}
        &= D_{\psi}(\widehat{\xi}_{t+1}),
        & \widehat{y}_{t+1}
        &= C\widehat{s}_{t+1}.
    \end{aligned}
    \label{eq:koopman_model}
\end{equation}
Here $\xi_t$ is the encoded memory state, the space in which the
affine step and the later rollout operate.
$K\in\mathbb{R}^{d_{\xi}\times d_{\xi}}$ describes latent evolution,
$B\in\mathbb{R}^{d_{\xi}\times 1}$ describes command dependence, and
$b\in\mathbb{R}^{d_{\xi}}$ is a bias. We write
$g_{\psi}=C\circ D_{\psi}$ for the attribute readout.

The shared $K$ and the affine command dependence are modeling
restrictions, rather than consequences of the operator's linearity. In
particular, we do not assume an exact finite-dimensional Koopman
representation of the LLM. Moreover, $g_{\psi}$ need not be linear, so
linear latent dynamics do not imply a linear map from latent states to
output attributes.

The encoder and decoder need not do any work at all. One member of this
family sets $E_{\phi}$ and $D_{\psi}$ to the identity, so the operator
acts on the raw memory state $s_t$ with no learned lifting. This
linear, delay-embedded case is the instance this paper examines, and it
keeps the same affine transition and command column as the general
form.

The operator, and any learned lifting, is fit offline on recorded
transitions built from overlapping history windows, held fixed during
test-time control, with its training objective in
Appendix~\ref{app:A1_estimator}.

\subsection{Predictive Candidate Selection}
\label{sec:control}

\textbf{Why Scoring Happens Without Opening the Model.} Planning on a
lifted linear predictor is standard model-predictive control, so the
open question is how a candidate gets scored without opening the model
that would otherwise generate it. Each candidate is compared only on
the reply attributes it is predicted to produce, never on any quantity
internal to the model. This is what lets the controller run against an
interface that returns text alone. \uline{A candidate is judged only by
the reply attributes it is predicted to produce, never by anything
inside the model that would produce them.}

At each iteration, let $\mathcal{C}_t\subseteq\mathcal{C}$ be a
nonempty finite set of admissible candidate commands. Evaluating a
candidate needs only holding its command fixed over a lookahead and
propagating the encoded state forward, with no further generation from
the frozen model. We hold each candidate's command fixed over a
prediction horizon of $H$ interactions, truncated to the remaining
interaction budget, and propagate the state starting from the current
observed memory:
\begin{equation}
    \begin{aligned}
        \widehat{\xi}_{t\mid t}(c)
        &= E_{\phi}(s_t),\\
        \widehat{\xi}_{t+h\mid t}(c)
        &=
        K\widehat{\xi}_{t+h-1\mid t}(c)+Bc+b,\\
        \widehat{y}_{t+h\mid t}(c)
        &=
        g_{\psi}\!\left(
            \widehat{\xi}_{t+h\mid t}(c)
        \right),
        \qquad h=1,\ldots,H.
    \end{aligned}
    \label{eq:rollout}
\end{equation}
Here $\mathcal{C}_t$ is the admissible candidate set at step $t$, and
$H$ is the prediction horizon in interactions.

Because the latent transition is affine and the command enters as one
column, propagating several steps ahead collapses into a matrix power
rather than a step-by-step loop. The latent trajectory has the explicit
form
\begin{equation}
    \widehat{\xi}_{t+h\mid t}(c)
    =
    K^h E_{\phi}(s_t)
    +
    \sum_{j=0}^{h-1}K^j(Bc+b).
    \label{eq:closed_form_rollout}
\end{equation}
Candidate evaluation therefore costs a latent propagation and a decode,
not another query to the target LLM.

Scoring a candidate on its whole predicted trajectory, rather than its
immediate effect, lets the controller pick a command that differs from
the target while the attribute is still moving. We score each candidate
using its predicted trajectory's deviation from the desired attribute:
\begin{equation}
    \begin{aligned}
        \widehat{J}_t(c)
        &=
        \sum_{h=1}^{H}w_h
        \left|
            \widehat{y}_{t+h\mid t}(c)-r
        \right|^2,\\
        c_t^{\star}
        &\in
        \operatorname*{arg\,min}_{c\in\mathcal{C}_t}
        \widehat{J}_t(c),
        \qquad w_h\geq 0.
    \end{aligned}
    \label{eq:selection}
\end{equation}
Here $w_h$ weights the deviation at horizon step $h$, and
$\widehat{J}_t$ is the predicted cost of holding a candidate command
over the horizon.

The controller executes only the next intervention
$u_t=\mathcal{P}(x,\mathcal{H}_t,c_t^{\star})$. After receiving
$o_{t+1}$, it evaluates $y_{t+1}=V(o_{t+1})$, shifts the memory window,
and repeats the optimization from actual observations rather than a
previously predicted memory. The constant-command assumption applies
only within a hypothetical rollout; the executed command can change at
every real interaction. Candidate simulation adds no target-LLM
queries, although any cost of constructing candidates or evaluating
responses still counts toward the inference budget.

Accurate prediction on fixed-command training trajectories alone does
not establish accuracy after command changes. Control additionally
depends on coverage of the command-history pairs encountered at
inference time.

\subsection{Prediction Error and Intervention Selection}
\label{sec:analysis}

\textbf{What does predictive accuracy buy for the command that gets
selected?} We give a conditional analysis connecting predictive
accuracy to the quality of candidate selection. For a candidate $c$,
let $s_h^c$ and $y_h^c$ denote the actual memory state and attribute
after $h$ further interactions that repeatedly apply $c$ from the
current state. Define $\xi_h^c=E_{\phi}(s_h^c)$, with $s_0^c=s_t$.

Suppose that, uniformly over the candidate rollouts,  % GATE-EXEMPT: adverb uniformly -- mathematical quantifier over the rollout index, not an intensifier
\begin{equation}
    \begin{aligned}
        \xi_{h+1}^c
        &=K\xi_h^c+Bc+b+\eta_h^c,
        &
        \|\eta_h^c\|_2
        &\leq\varepsilon_{\mathrm{dyn}},\\
        y_h^c
        &=g_{\psi}(\xi_h^c)+\nu_h^c,
        &
        |\nu_h^c|
        &\leq\varepsilon_{\mathrm{rec}}.
    \end{aligned}
    \label{eq:residual_assumptions}
\end{equation}
The bound $\varepsilon_{\mathrm{dyn}}$ limits the one-step latent
residual, and $\varepsilon_{\mathrm{rec}}$ limits the residual left in
the readout itself. These residuals include imperfect finite-memory
closure, model approximation, and generation variability. Assume
further that $\|K\|_2\leq\kappa$ and that $g_{\psi}$ is $L_g$-Lipschitz
on the relevant latent region. For stochastic generation, the
results below hold on the event that these residual conditions are met.

Because the predicted and actual latent rollouts start from the same
encoding, their gap grows only through the accumulated one-step
residual carried through the readout.
\begin{equation}
    \left|
        y_h^c-\widehat{y}_{t+h\mid t}(c)
    \right|
    \leq
    \varepsilon_{\mathrm{rec}}
    +
    L_g\varepsilon_{\mathrm{dyn}}
    \sum_{j=0}^{h-1}\kappa^j
    \;\triangleq\;\Delta_h.
    \label{eq:prediction_bound}
\end{equation}
Here $\Delta_h$ is the resulting $h$-step attribute prediction error
bound, and it trades off against the horizon $H$: a longer horizon
covers more distant consequences but needs accurate dynamics over more
steps. If $\kappa<1$ the geometric sum is bounded by $1/(1-\kappa)$,
and no such contraction is assumed for the learned model. The gap
between a candidate's actual held-command cost
$J_t(c)=\sum_{h=1}^{H}w_h|y_h^c-r|^2$ and its predicted counterpart
$\widehat{J}_t(c)$ accumulates only through this same per-step error.
Let $R$ bound how far any attribute, actual or predicted, sits from the
target across candidates and prediction steps.
\begin{equation}
    \left|
        J_t(c)-\widehat{J}_t(c)
    \right|
    \leq
    2R\sum_{h=1}^{H}w_h\Delta_h
    \;\triangleq\;\delta_J.
    \label{eq:cost_bound}
\end{equation}
Here $\delta_J$ bounds the gap between the predicted and actual
held-command cost.

Let
$c_t^{\mathrm{opt}}\in\operatorname*{arg\,min}_{c\in\mathcal{C}_t}J_t(c)$.
Applying the cost bound twice around the definition of $c_t^{\star}$
gives
\begin{equation}
    \begin{aligned}
        J_t(c_t^{\star})
        &\leq
        \widehat{J}_t(c_t^{\star})+\delta_J\\
        &\leq
        \widehat{J}_t(c_t^{\mathrm{opt}})+\delta_J\\
        &\leq
        \min_{c\in\mathcal{C}_t}J_t(c)+2\delta_J.
    \end{aligned}
    \label{eq:selection_bound}
\end{equation}
This places the selected command's actual cost within twice the best
candidate's cost-estimation error, for the current held-command
comparison rather than the cumulative cost of the replanned closed
loop. It does not guarantee that the candidate set contains an
intervention able to reach $r$, nor that the closed loop converges.
Re-observation resets the rollout's initial latent error, but it does
not eliminate model mismatch or guarantee exact target tracking.
\uline{Predictions that stay accurate across the rollout keep the
selected candidate's cost within twice the best achievable estimation
error, for this one held-command comparison.}
